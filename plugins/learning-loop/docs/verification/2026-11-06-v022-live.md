## Scope and implementation

Selected three behaviors from Hermes [81a55437 to b7736eca](https://github.com/NousResearch/hermes-agent/compare/81a55437f3f31a9f12a30c53b6c5d49d420898aa...b7736eca98cc6919b7b7f1d52dc1c45946793648):

- Memory evidence guidance rejects guesses from topic/tone and one-off requests as standing preferences. Added to fresh agent prompts and the production review prompt.
- Over-limit stores accept remove-only recovery and duplicate-add no-op. Removing or legally shortening an individually oversized entry first backs up exact original file bytes with exclusive creation, 0600 permissions and sync. Backup failure preserves text, metadata and pending approvals.
- New or changed skill descriptions must fit 60 characters. Unchanged legacy descriptions still allow body/supporting-file maintenance. Normal staging, CAS and batch atomicity remain in force.

This is a selective adaptation, not full upstream parity. The original broad UPSTREAM baseline remains, with an additional source record scoped to these three paths. No native history/indexing implementation was changed; no old provider resume/refetch path was introduced.

## Backup and rollback

Previous version: 0.2.1 (`ed7cca337021c32183d8ecf843b4ed199f9d1523`). Before installation, the state directory and exact settings were backed up privately; SQLite's online backup preserved the session index. Fixture cleanup copies and precise local recovery paths remain in the private verification archive.

For rollback, first gate on no running/queued reviews, save the **current** settings and state, remove only the learning-loop registration, restore saved settings before reinstalling the previous retained snapshot with the same plugin ID, then check health/settings/process identity. Do not restore the whole old state backup over newer real writes. The old runtime does not know v4 bindings: sessions created after this upgrade must be accounted for and recreated before relying on old-runtime tools. No rollback was executed.
