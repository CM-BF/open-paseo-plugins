# Paseo Board 插件：方案草案

本文件是供讨论的计划，不代表已实现或已安装。用户目标：把人与 agent 的主要交流放在按任务生成、持续更新的项目 board 上，减少 chat noise；复用 paseo-visualize 与 paseo-async-shell。2026-10-28。

## 推荐形态

**产品定义：Board 是可持续更新、增加人–agent 交互机制的 visualize。完整自由交互内容就是主体。**

新插件暂名 `paseo-board`。一个项目对应一个持久入口，可以包含多个工作区、任务和 agent。板的身份与状态不随某个会话结束而消失。这是通用的人–agent 交流方式，任务内容和组织方式由 agent 决定。ML 实验只是说明它如何使用的例子，不能成为产品定位、内核 schema 或固定页面。每块 board 有一个负责人，可以随时开隔离上下文的分支；负责人和关联分支都能按用户要求更新同一画布。

board 的主体是 agent 自由构建、完全可交互的内容，表达自由度至少与 paseo-visualize 相当。agent 可以写任意 HTML/CSS/JS、SVG、Canvas/WebGL、动画、模拟器、输入控件和它们的组合；不限定组件目录、卡片类型、固定网格或业务 schema。图表、短文、文件和布局只是可选表达，不能降格为插件固定外框里的小型展示区域。

插件提供持久身份与更新、上下文选区与 fork、agent 默认决策提取与索引、问题和结果的关联。这些能力通过紧凑工具条、快捷键、选区浮层和按需抽屉进入；不要求画布常驻显示决策表、活动流、聊天栏或“待处理”卡。决定在信息上重要，不等于永久占据大块屏幕。大部分可见空间与交互由 agent 自己构建。

agent 的回复可以直接成为画布上的新内容或新交互：为解释一个问题插入可播放动画，给用户指向的图旁添加模拟器，在指定空白处增加比较面板，或重组局部表达。用户可直接说“在这里加一个东西”，不必先创建卡片或选定预设模块。聊天保留为原始记录、深入讨论和故障恢复入口；画布应能承载完整交流，不要求每次回答都回到侧边文本线程。

## 三种方案

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| Chat + 自动摘要 | 接入快 | 用户仍要阅读、重建状态；纠正要求缺少稳定落点 |
| 每次生成互不关联的 HTML 快照 | 表达自由度高 | 缺少连续身份、上下文定位与运行状态延续 |
| 持续的自由交互画布（推荐） | 保留完整 HTML/JS 表达与交互能力，并补上上下文交流、更新与历史 | 需要版本、定位、交互回执和运行状态延续机制 |

## 小内核与开放边界

固定协议只负责持久画布、锚点、事件与交流记录；不规定画布内必须是什么对象。决策、讨论和更新记录由协议关联到内容，不能反过来要求所有内容先映射成固定 schema。

- 画布：稳定身份、内容/资源版本、负责人和更新时间；内容是自由代码与资源，可以选择绑定开放 JSON 数据。语义对象 ID 与结构化数据绑定是可选能力；纯 SVG、Canvas 或没有节点 ID 的 HTML 也能使用。
- 运行状态：内容代码、业务数据和交互状态分开处理。普通数据更新应保留输入、视口、动画进度和已有组件实例。agent 可以替换局部内容，也能明确重建整张画布；任意代码重写无法保证自动迁移所有状态，因此提供可选保存/恢复钩子，迁移失败有明确恢复路径，不能静默丢掉用户输入。
- 锚点：用户可指向语义对象、DOM 片段、文字、图像区域或任意空白位置；附原文/截图、坐标、布局与内容版本。无需先创建对象才能提问或要求插入内容。
- 事件：外部观察、agent 更新、用户输入有不同来源，携带去重 ID 与时间。可观测事实直接入板，涉及解释或下一步行动时才唤醒 agent。
- 意图：用户对项目或对象提问、纠正、选择、补充约束。记录用户看到的版本、原文、接收与处理状态，以及实际结果。

内核只负责存储、关联、传递与回执；模型决定怎样理解任务、怎样画、何时调用工具和怎样推进。新任务不需要开发一套新工作流。更强的模型可以提出更好的解释、信息组织和事件监听方案；插件仍需维护 SDK 兼容性，不能保证永不淘汰。

## 注意力设计

普通进展原地更新，默认不响铃、不弹窗、不追加一屏消息。默认关注三类事情：需要用户选择；已约定的结果、时间或约束失效；用户主动订阅的结果到达。用户可以调节每个项目的提醒规则。

进入项目保留 agent 设计的主体画布，并提供按需查看的“上次查看以来”：结果改变、重要决定、仍待处理。已读只移动阅读位置，绝不等于批准。更新不把正在操作的内容移走；同一内容的连续变化合并展示。事实、agent 判断和待验证假设分别标明来源。失联或过期显示未知/最后核对时间，不以绿色“完成”掩盖。

全局首页按“需要我处理”聚合项目，保留全部项目入口，避免运行任务数量占据注意力。

## 默认决策记录

记录会影响结果或用户预期的默认选择：范围、兼容性、成本、重要依赖、可见行为、关键假设、会产生返工的取舍。无需记下每次工具调用和内部思考。

记录：选了什么、简短理由与证据、影响、当时依据的用户要求、是否已执行、可否撤销、重议条件、后续替代决定。标识“agent 自主决定 / 用户指定 / 从行为推断、待核对”。记录不意味着每件事都请求批准；在现有授权内照常推进。

“提取 agent 的默认决策”是核心机制，不应只靠 agent 自觉写日志。采用三条互补渠道：

1. agent 在作出重要选择时主动记录，成本最低，也最接近当时理由。
2. 从已外显的对话、工具参数、配置差异和运行元数据中增量提取。按里程碑/回合批处理，模型只负责判断与归并，插件保存原始证据位置、提取进度和来源。是否新增模型调用、使用哪个已有 agent/profile 及预算须在实施时明确；不默认接入额外付费服务。
3. 在实验启动与完成等关键节点核对“运行事实是否有相应决定”：例如训练预算缩短、seed 数减少、过滤了样本。没有理由就写“理由未说明”，不能由提取器编造。自动提取的决定标为“从行为提取”，agent 补充的事后解释单独注明。

按同一对象/选择归并重复记录，保留修订和 superseded 关系；按影响范围、结果可比性、成本与可逆性挑选首页内容，其余可检索。每条决定关联它影响的方法/运行/结果，形成“选择 → 受影响实验 → 比较结论”的可追溯链。用户可以顺着 figure 看到背后的默认取舍。

ML 示例：agent 默认只跑一个 seed，结果却与三 seed 基线比较；为赶预算把训练从 12 epoch 降到 8；修改数据过滤规则但沿用旧 baseline。记录的主语是 agent，状态是已采用/已执行/被替代/来源待核对，不把这些混成“等待用户批准”。

插件不能捕获从未外显、也没留下行为证据的内部想法。界面显示“已核对到哪个回合/运行”，不虚称完整覆盖。修正旧决定保留历史，并说明已完成工作中哪些受影响。

提取结果再按证据性质分层：

- **已说明的决定**：agent 明确说了选择与理由，附原文或主动记录。
- **观察到的行为变化**：参数、配置、被关注输入或输出发生变化，可以机械比对；这证明变化发生，不自动证明其重要性或动机。与已有决定关联后，仍缺理由的标“理由未说明”。
- **可能的默认决定**：从已外显内容推断，单独呈现、可纠正，不作为事实或授权触发动作。按误判和重复率控制提取量。
- **用户要求**：独立保存，作为核对 agent 取舍的依据，不能归因成 agent 自己的决定。

高信噪比不能以用户没提出异议作为正确性证明。未读、未质疑和已同意分别处理；关注度降低不删除重要取舍的证据。

## 框选并 fork：插件固有能力

用户选中文字、图中一个区域、多个结果或空白位置 → 提问/请求原地增补，或选择“开 fork” → 带上下文的请求。fork 像 /btw，只隔离主会话的对话上下文，共享同一块 Board。用户在分支提出修改，分支直接修改同一画布；解释也可放在问题旁的自由输出空间。执行 agent 可以继续当前任务；不同会话的修改仍通过版本冲突检查协调。回答也可以生成附着于选区的动画、模拟器、figure 或注释，不要求用户切回长聊天流。

选择上下文包含 boardId、视图与数据版本、对象 ID（例如实验 run、候选方案或行程段）、原文字引用或图片快照与选框坐标、相关决策和证据、用户问题。选择时冻结版本，避免实时更新把提问对象换掉。图表有语义标注时带上原始数据点；无标注时仍保存图像、坐标和页面文字作为退路，并明确上下文有限。

选区能力由插件注入与渲染器桥提供，不要求每个 agent 手写一套选区 UI。默认处于正常交互模式，插件不能截获 agent 页面中按钮、滑杆、拖拽、绘图、缩放和输入。只有用户主动进入指向/框选模式时才接管对应手势，退出后恢复；触摸和快捷键均需验证。桌面支持文字与区域引用。手机提供兼容界面，不限制桌面自由画布与完整交互能力。

位置请求可以是“在这段下面”“替换这个图”“在右边空白加一个动画”。优先用稳定锚点表达关系，缺少语义锚点时使用当时的画面和几何区域。若当前布局已变化，先尝试重新定位并展示目标；无法可靠映射时保留原请求与预览，不随意插到另一个位置。局部更新后用户可追溯该次请求与新内容版本。

fork 的用途由用户在其中提出的请求决定，与主 chat 一样可以解释、修改或执行相关工作，不需要先“带回主线”。关联分支可以读取并更新同一 Board、记录自己的默认决策和事件，但不能更换负责人，也不能代写其他 agent 的交互回执。局部解释可以保留在问题标记旁；画布修改直接 publish 到原 Board，并使用最新版本避免覆盖并发编辑。旧 return 操作保留兼容，可用于用户主动转告负责人。

“已落实”需要指向新内容版本、产物或验证结果，并满足该建议对应的要求；只有 agent 说“收到”或附了一个链接并不够。分支默认只携带选区、相关状态/决定与证据指针，不复制全部聊天；需要更多上下文时按来源继续读取。

分支与原会话使用来源链接关联；不能随意设置 parent，因为实际父子关系会造成父归档时连带归档。当前公共 SDK 没有直接的 fork 方法。已核对：Paseo app 自带 fork 也以时间线导出文本/chat_history 附件创建新 draft，不能理解为 provider 内部 session 原样克隆。因此 plugin-only 路径可用 public agents.create + 选区/历史/决策快照实现讨论分支，保留来源链接；attachment 类型、provider 图像支持与工具权限在阶段 0 实测。不得调用 SDK 私有入口冒充公共能力。

## 事件与交流闭环

外部结果 → shell 发布结构化事实 → board 保存新版本 → 视图更新。需要解释或行动时，既有 async-shell sendback/结束通知唤醒负责人；负责人读取增量、决策记录和未处理意图，再写回结果。首版让 board 事件入口仅负责落盘与更新界面，避免与 async-shell 同时成为唤醒源。

用户点击对象并发问 → 插件保存带对象/版本的意图 → 通过 Paseo SDK 发给绑定 agent → agent 回写与该意图关联的解释/修改 → 板上显示结果。区分“已保存、已排队、已送达、正在处理、已落实、失败”，消息送达不是执行完成。重试复用意图 ID，界面保留输入；对基于旧版本的实质修改检查前提，不能盲目执行。

每个接入脚本需有明确数据源、检测条件、频率/期限、去重与停止方式。“任意事件”指 agent 可以写适配脚本，不意味着所有第三方都已具备连接器。高频读数直接更新数据，按阈值/异常/里程碑合并后唤醒。外部文本保留为外部事实，不直接提升为用户授权。

## 插件实现边界与复用

已核对本地源码与当前公开插件文档，尚未运行产品原型。

- Paseo 已提供 screen、workspace panel、原生控件、typed RPC、agent send、生命周期入口。新插件可以先独立实现，不把核心修改作为前提。
- visualize 当前是按文件路径缓存的快照；成功后 `staleTime: Infinity`。它的主题、HTML 沙箱、导出和 follow-up 思路可复用，但没有现成跨插件 live-render API。实施前选择提取一个版本化的小渲染模块，或在新插件中引入经过核对的最小渲染适配器；不直接 import 相邻安装目录的内部文件。现有 visualize 快照保持其语义。
- 新插件拥有 board 数据。桌面通过插件 RPC 取版本增量，再用受控 frame bridge 把状态注入视图。HTML 不自己连接 localhost/WebSocket；沿用沙箱，桥只接受当前 board 的有限操作。
- 首版可在面板可见时以 1–2 秒目标间隔做带 revision 的轻量查询，隐藏时停止或放慢，重连后补取。此为待测目标而非已达到的实时性能。不宣称现有 SDK 已提供自定义 board 推送通道。
- async-shell 直接沿用后台运行与回信。新增 board CLI（名称提案 `paseo-board emit`）让脚本写入结构化事件；CLI 与 MCP 经过同一个插件服务做校验、去重和落盘。不读取 async-shell 私有 task JSON，也不另造进程管理器。
- 桌面自由交互画布是首要交付。用户已明确允许手机兼容版；手机宿主缺少 HTML 运行时时，提供原生摘要、决策和交流入口并明确标注能力。不得为手机版本限制桌面 HTML/JS、动画或交互。

## 接口草案（均为建议名称，不是现有 API）

1. `board.read(boardId, sinceRevision?)`：状态、增量、未处理意图、来源与新鲜度。
2. `board.publish(boardId, expectedRevision, update, eventId)`：发布自由代码/资源，或更新可选绑定数据与必要的决策记录；允许增补、局部替换与明确的整页重建，不能限定为填充固定卡片。版本冲突返回最新版本，禁止悄悄覆盖用户修改。
3. `board.interact(boardId, anchor?, seenRevision, intentId, text)`：先保存用户意图，再投递；anchor 可以指向对象、片段、文字、区域或空白位置，结果关联 intentId。
4. `board.events` / CLI `emit`：同一入口接收 shell 事实，带 source 与去重 ID。

固定 UI 的 `selection → fork` 由插件自己的服务完成；agent 可用 `board.interact` 相关协议读写分支结果。API 命名在阶段 0 收敛，不把选择交互强加成 agent 的任务流程。

首次 publish 可创建 board。常用“记录决策”可以是 publish 的便利入口，而不是新的业务引擎。客户端、MCP、CLI 使用同一份类型和校验规则。

## 数据与恢复

插件数据目录保存版本化状态与追加事件，单项目单写队列；选择一个可保证事务的存储方案，状态与事件提交为一个事务。HTML 视图按内容版本存储。最初不引入通用事件平台、CRDT 或任意图式工作流引擎。

重连从已读版本恢复；重复事件按来源与 eventId 去重；乱序数据检查源序号或观察时间；无可靠顺序时标明不确定。多个 agent 先通过一个负责人合并，后续再细化对象写入权限。

板的存续独立于 agent。当前 async-shell 仍归属于 owner agent：owner 归档会停掉 shell 并丢弃待回消息。因此板上必须显示“负责人/监听已停止”，提供重新绑定和重建监听；不能宣称归档后监听永久有效。重新绑定不自动扩大原授权，旧 agent 的迟到回复需检查负责人代次和版本。重启恢复以实际进程/事件核对为准。

## 实施顺序与验收

### 0. 小范围复用验证

在隔离测试环境核对目标 Paseo app/daemon/SDK 版本；首先验证目标桌面客户端的自由交互运行时，包括 JS、SVG/Canvas、动画、输入、拖拽和桥接。随后注册 panel + RPC；验证状态注入、局部更新、CLI → board、选区 → 新讨论 agent 的上下文与权限。选定渲染代码复用方式。产物是明确的平台能力表与可运行通道；不能用静态截图通过交互验收。

### 1. 一张真正可协作的板

持久画布 + agent publish/read + 完整自由 HTML 交互 + 定位增补/选区 fork + 意图回执 + 决策记录与增量提取。用这份设计本身做第一张板：用户指向一处要求“在这里加动画解释”，agent 原地生成可播放、可操控的内容；旁边已有输入和组件状态不重置。用户可继续在新动画上追问或开分支。默认取舍被提取并关联依据，决定抽屉按需打开。再换成其他任务表达，验证机制无需新增业务逻辑。

### 2. 接入 async-shell 的一个真实事件

沿用 async-shell 接入一个 agent 自选的外部事件源：文件变化、任务结果或已有日志流。agent 自定事件内容，写入同一板。普通数据不唤醒，失败/里程碑按脚本规则 sendback。agent 离开回合后依然更新板；同一事件重复投递只生效一次。用户把 fork 建议送回后，主 agent 记录新的取舍并更新同一板。验证断线、重连、负责人停止与失败回执。阶段 1+2 构成最小可用版本，不能以只有展示的阶段 1 宣称全部完成。测试使用受控的低成本事件源。

### 3. 多项目与注意力视图

从每张板派生“需要你”和“自上次查看变化”，增加项目导航、阅读位置与提醒偏好。先单 host，多 host 路由另行验证。

### 4. 证明通用性

选取实验迭代、资料研究和行程/办事规划等不同任务验证：agent 能生成不同的交互内容与事件脚本，内核接口保持不变。依据真实使用改进性能、移动手势和多 agent 并发。各宣称支持的平台都必须满足自由交互要求。

验收标准：用户隔天回来，30 秒内说明当前状态、agent 的重要取舍和下一步；不翻 chat 就能发现一个隐藏默认决定；框选文字/图片后 fork 带对内容版本、相关数据和决定；新 idea 可以送回并看到落实结果；普通进展不重复发送通知；断线/重试不丢意图、不重复执行。用一组含已知默认取舍的任务记录评估提取遗漏、误判和重复，并展示来源覆盖范围，避免“提取一堆无关决定”降低信噪比。

同时记录 agent 维护板面所用的 token 比例、唤醒次数和用户通知次数。后台持续变化不应要求模型持续在线。首个可用版本仍包含自由可视化、选区讨论与决定提取；原生文字通道可以用于早期连通性测试，不能替代自由表达这一核心能力。

## 已识别风险与未决项

- 最大产品风险是板成了另一份要读的长报告：用用户回访与纠正任务测试，而不是卡片数量。
- 最大实现风险是视觉好看但状态不可信：先保证版本、来源、回执与恢复。
- 复用渲染器的打包形式待阶段 0 验证；无现成跨插件可调用接口的证据。
- 1–2 秒更新目标待测；不承诺逐 token 生成界面。优先刷新事实与完整语义片段，避免不停重排。
- 手机完整交互运行时不在桌面交付关键路径；兼容模式必须标明限制。
