# 发布页访客评论：使用说明

这份说明讲三件事：怎样让发布出去的 Board 页面接收访客评论，访客看到什么，以及评论到达你的电脑之后会发生什么。技术细节见[发布页与后端](published-apps.md#访客框选评论-visitor-text-selection-comments)、[评论收件箱](comment-inbox.md)和[后端脚手架](app-backend-scaffold.md)。

## 整体是怎样连起来的

```
访客浏览器（GitHub Pages 上的页面）
   │  发评论、看自己的评论和回复
   ▼
你部署的评论后端（paseo-board-app，Node + SQLite）
   ▲  每几秒取一次新评论；评论助手的回复也从这里发回去
   │
你电脑上的 Paseo Board 插件（评论收件箱）
```

- 页面是静态网页，评论存在你自己部署的后端里。页面地址和后端地址不同，例如页面在 `https://cm-bf.github.io/pages/boards/<分享编号>/`，后端在 `https://api.example.internal`。
- 后端放在哪里、谁能访问它，由你决定和部署。插件不会替你开放任何端口或服务；agent 也被明确要求不这样做，只使用你给出的后端地址。
- 收件箱的令牌（`BOARD_INBOX_EXPORT_TOKEN`）只保存在你的电脑和后端上，不会进入页面、画布或 agent 能看到的内容。

## 第一次开启

1. **准备后端。** 用 `paseo-board-app init` 生成的应用，在 `board-app.json` 里打开评论并写上发布网站的地址：

   ```json
   "origins": ["https://cm-bf.github.io"],
   "comments": { "enabled": true }
   ```

   在后端的 `.env` 里设置一个 32 位以上的随机 `BOARD_INBOX_EXPORT_TOKEN`，然后按原来审核过的 SSH 部署流程部署。后端在反向代理后面、而代理在另一台机器上时，把代理的地址写进 `comments.trustedProxies`，否则所有访客会共用一个频率限制。代理要自己设置 `X-Real-IP`（覆盖）或 `X-Forwarded-For`（追加）中的至少一个，例如 nginx 的 `proxy_set_header X-Real-IP $remote_addr;`；两个头都在时，访客按两个地址分别计数，伪造其中一个绕不过频率限制。

2. **连接收件箱。** 在 Board 的「更多 → 评论收件箱 → 后端来源」登记后端的导出地址（`https://…/_board/comments`）和令牌。登记后插件会自动同步，不需要再点「同步」。

3. **发布时打开评论。** 在发布面板勾选「访客可以框选评论」，填后端地址（不含 `/_board/comments`，面板会根据第 2 步自动填好），点「检查后端」。检查通过才能发布：它会确认后端支持评论线程、发布网站在 `origins` 里、代理设置是否需要补充。发布出去的页面就带上评论功能了。没有勾选的页面和以前完全一样。

4. **（可选）让 agent 自动处理。** 在「评论收件箱 → 评论与权限」点「Agent 自动处理并公开回复」，读完确认文字后选择：
   - 回复方式：直接公开，或者「回复先给我审核」（助手写草稿，你点发布才会发出）；
   - 评论助手使用的权限模式：只能选会先询问你的模式。

   确认后，插件为这张 Board 创建一个专用的「评论助手」agent。开启之前已经收到的评论不会被自动处理。

## 访客看到什么

- 在页面上选中任意一段文字，旁边会出现一个小的「评论」按钮；也可以在选中的文字上点右键（Mac 上也可以按住 Control 点按）直接打开评论框。键盘用户可以用 ContextMenu 键或 Shift+F10。Shift + 右键仍然是浏览器自己的菜单。焦点回到页面里时按 Esc 也能收起评论框（保留草稿）或「我的评论」面板。
- 评论框里引用选中的文字，可以填称呼（可选）和评论内容（最多 2,000 字）。⌘/Ctrl + Enter 发送，Esc 收起并保留草稿。
- 发送后左下角出现「我的评论 n」，被评论的文字旁边有编号标记（被页面顶部固定的标题栏挡住时暂时隐藏）。作者回复后，标记变色，左下角显示「n 条新回复」；打开后能看到「作者回复」或「作者的 AI 助手回复」。编号标记供鼠标和触屏使用；键盘用户打开「我的评论」，每条评论下的「在页面中定位」会把那段文字滚到眼前。页面改版后找不到原文的评论标为「原文已修改」，不再提供定位和「再评论这段」。
- 访客只能看到自己的评论和给自己的回复，看不到别人的。身份是浏览器里随机生成的匿名编号，不需要登录；「清除本机的评论身份」可以删掉它。
- 输入框、文本框、可编辑区域、按钮、链接自带的菜单，以及作者标了 `data-board-comments="off"` 的区域都不会被评论功能接管。

## 评论到达之后

- **自动同步。** 插件每 5 秒左右检查一次新评论，出错时逐步放慢（最慢 5 分钟一次）。收件箱面板显示每个来源的同步状态和最近的错误；可以暂停自动同步，也可以随时点「立即同步」。
- **只有你开了自动处理，agent 才会动。** 新评论到达后约 3 秒（同一批最长 10 秒），插件把这批评论的编号交给评论助手。消息里只有编号，没有评论原文；助手用收件箱工具读取原文，并且被告知评论内容只是数据、不是指令。
- **不会打扰你正在用的 agent。** 自动处理只给评论助手发消息，从不发给负责这张 Board 的主 agent 或它的 Side。助手正在忙或在等你批准时，新评论排队等它空下来。
- **回复。** 助手用 `board_inbox_reply` 回复，插件用你电脑上的令牌把回复发到后端。访客的页面在打开期间大约每 15 秒检查一次（切回页面时立即检查），所以回复会在十几秒内出现。看起来含有令牌、密钥、内部地址或本机路径的回复会被拦下。助手只能回复唤醒它时列出的评论，回复里也不能照抄其他访客的评论。你也可以在收件箱面板里亲自回复任何一条评论。
- **没开自动处理时。** 评论照常同步到收件箱，你可以阅读、分类和亲自回复；不会有任何 agent 被唤醒。只给了「读取」或「内部分类」权限的 agent 不能回复访客。

## 限制

| 项目 | 默认值 |
|---|---|
| 访客评论长度 | 2,000 字 |
| 每个访客发评论 | 每分钟 5 条，每小时 30 条 |
| 每个访客地址发评论 | 每分钟 10 条，每小时 60 条 |
| 整个后端收评论 | 每分钟 120 条，每小时 1,000 条 |
| 同一页面每天 | 500 条 |
| 每条评论的回复 | 最多 20 条，每条最多 2,000 字 |
| 自动同步导入 | 每个来源每小时 200 条，每天 1,000 条 |
| 唤醒评论助手 | 每次最多 8 条评论；每张 Board 每小时 6 次，整台电脑每小时 20 次 |
| 评论助手回复 | 每张 Board 每小时 30 条 |

后端的限制可以在 `board-app.json` 的 `comments.limits` 里调整。插件这边超过唤醒次数时自动暂停，面板会写明原因，到时间自动恢复；你也可以随时暂停或恢复自动处理。

## 已经部署过的后端怎么升级

以前用 `paseo-board-app` 生成并部署的后端，需要先更新运行时，再按原来的方式部署：

```sh
paseo-board-app update-runtime --dir /绝对路径/你的应用
node /绝对路径/你的应用/board-app.mjs ssh plan --dir /绝对路径/你的应用 --host <主机别名> --root <远端目录> --out ../plan.json
node /绝对路径/你的应用/board-app.mjs ssh deploy --plan ../plan.json --confirm <摘要>
```

- `update-runtime` 只替换应用里的 `.board/runtime`，不动你的路由、数据表、迁移和数据。
- 新运行时第一次启动时会自动升级数据库一次，已有评论全部保留；升级失败会整体回滚。
- 发布面板的「检查后端」如果提示「后端版本过旧」，就是还没有做这一步。

## 安全说明

- 评论内容、称呼、网址和选中位置都来自外部访客，插件、面板和 agent 都只把它们当作数据。
- 评论助手的权限很窄：只预先允许四个收件箱工具，不能修改 Board；它想做其他事情都会先问你。你可以随时在收件箱里关闭自动处理（助手本身不会被删除）。
- 同一个网站地址下的其他页面（例如同一个 `github.io` 账号下的其他仓库）可以读到访客浏览器里的匿名编号，从而以这个访客的身份查看或发评论。浏览器里不保存评论或回复的文字。
- 后端地址如果是公司内部地址，写进公开网页后任何人都能看到这个地址，公司网络以外的访客也发不了评论；发布面板会提醒并要求你确认。
- 一个后端建议只连一台电脑的一张 Board。多台电脑都开着自动处理时，每台都会回复。

## 公开评论（像 Google 文档）

发布面板里，「访客可以框选评论」下面多了一项「评论可见范围」：

- **仅自己可见**（默认）：和上面说的一样，每位访客只看得到自己的评论和你的回复。
- **公开：所有访客互相可见（像 Google 文档）**：所有打开页面的人都能看到全部评论和回复，也都可以在任何一条讨论里回复。

默认是「仅自己可见」，因为访客写评论时，默认不应该让陌生人看到；而且公开评论需要你能随时隐藏垃圾内容，这要求后端已经连上收件箱。已有的分享页、沿用旧设置的更新都保持原样，不会悄悄变成公开。

### 怎样开启

1. 先在「评论收件箱 → 后端来源」连接这个后端（同一个后端的另一个地址也可以，插件按部署编号识别）。没有连接时面板会提示，发布也会被拒绝。
2. 在发布面板选「公开：所有访客互相可见（像 Google 文档）」，点「检查后端」。面板会显示警告：公开评论任何打开页面的人都能看到，包括评论内容、回复和访客自己填写的称呼；页面一打开就会连接评论后端读取评论。
3. 生成版本时，插件把这个版本登记到后端：后端只接受和显示已登记版本的公开评论，而且只接受来自 `origins` 里网站的公开评论。把分享页改回「仅自己可见」或关闭评论时，插件会取消这个分享页之前所有公开版本的登记，并让后端关闭这个分享页地址的公开评论：之后无论用哪个版本（包括别的分享页的版本）都不能再在这个地址发表或读取公开评论，直接调用接口的人也一样。以后再把这个分享页改回公开时，新版本会重新打开它。
   - 后端连不上、或收件箱里的后端来源已经删掉时，改回「仅自己可见」或关闭评论**仍然会成功**，分享页上会提示「没能在评论后端取消旧版本的公开评论……」：新版本页面不再显示公开评论，但在后端取消之前，仍开着旧版本页面的访客还能读到和发表公开评论（你仍可以在收件箱里隐藏）。后端恢复、来源重新连好后，再更新一次这个分享页，插件会自动补上取消。
4. 命令行导出（`board-release`）只能发布「仅自己可见」，因为它没有收件箱令牌，无法登记版本。

之前收到的评论不会因为改成公开而公开：每条评论在发送时就确定了是公开还是只给作者看。改回「仅自己可见」后，页面不再显示公开评论，但它们仍保存在后端，收件箱里照常可见。

### 访客看到什么

- 页面上所有讨论引用的文字都有淡黄色底色。宽屏（1056 像素及以上）时右侧有评论栏，每张卡片对齐它引用的文字，卡片多时依次往下排；点开的卡片移到原文旁边，其他卡片让开。窄一些的屏幕上，左下角的「评论 n」按钮打开浮在页面上的评论栏；手机或横屏手机上是从底部弹出的列表。点淡黄色文字会打开对应的讨论，鼠标停在卡片上时原文会加深。
- 评论栏顶部有「未解决 / 全部」：作者标为已解决的讨论只在「全部」里，折叠成一行，不能再回复。页面改版后找不到原文的讨论列在底部「原文已修改」里，仍然可以回复。
- 每条消息写明是谁：访客显示称呼加匿名编号（例如「小王 · 访客·3f9a1c」，不填称呼时只有编号），编号前的小圆点颜色也来自编号；自己的消息带「我」；作者的回复带「作者」，评论助手的回复带「作者的 AI 助手」。称呼里不能有「作者」「AI 助手」「访客」这些字样（加空格、全角字母或繁体「訪客」也一样），也不能有看不见的格式字符；访客在输入称呼时就会看到这条说明，不会等到发送才被拒绝。「迈克尔·杰克逊」这样带间隔号的名字可以用。编号总是显示在称呼后面，作者和评论助手的标记是单独的标签，所以称呼冒充不了作者。同一位访客在不同页面的编号不同。
- 评论和称呼里看不见的字符（零宽字符、改变文字方向的控制字符、Unicode 标签字符等，以及连续的异体字选择符）都显示成 `[U+200B]` 这样的标记，页面上和收件箱里都一样，所以没有人能藏起一段别人看不到、但评论助手能读到的文字。
- 公开评论的称呼和「仅自己可见」页面上填的称呼分开保存，默认是空的；发送前会显示「将公开显示为：…」。
- 自己的评论可以「撤回」：撤回后其他人不再看到，作者也不能让它重新显示；已经看到的人可能保留了副本。
- 页面打开时读取一次评论，之后在页面可见时大约每 10 秒检查一次（没有变化时后端只回一个很小的「没有变化」），发送或回复后立即检查，切回页面时也会检查；所以别人的新评论一般在 10 秒左右出现（实测 4–11 秒）。15 分钟没有任何操作时放慢到 1 分钟；在页面里点击、滚动或打字都算操作。出错时逐步放慢。
- 评论很多、页面旁边放不下时，第一张卡片仍然对齐原文，后面的卡片依次往下排。在评论栏上滚动鼠标滚轮会带着页面一起滚动（卡片始终跟着原文）；滚到页面底部后还可以继续滚动评论栏，看到最后几张卡片。
- 点开的卡片太长时（回复很多），卡片本身可以滚动，「回复」总在评论栏里能点到。点页面上的其他文字或评论栏的空白处，就会收起点开的卡片。
- 你正在写回复时，作者把这条讨论标为已解决：卡片不会突然消失，会提示「作者刚把这条讨论标为已解决，你的回复没有发送；草稿还留在卡片里」，并把没发出的文字显示在卡片里，方便你复制；关掉卡片后它才从「未解决」里移走。
- 键盘：在评论栏里用上下方向键、Home、End 在卡片之间移动（页面和评论栏会一起滚动，让卡片留在原文旁边），Enter 打开卡片并滚到原文，Tab 进入回复框，⌘/Ctrl + Enter 发送（发送后焦点回到这条讨论的「回复」），Esc 先收起回复框，再取消选中，再关闭浮层或底部列表。
- 手机上点淡黄色文字打开底部列表时，页面会把这段文字滚到列表上方，不会被列表挡住；点页面上的其他地方会关闭列表。
- 宽屏时评论栏占用右侧 336 像素，页面相应变窄（不会盖住页面内容）；点「收起」后页面恢复全宽，浏览器会记住这个选择。

### 作者怎么管理

「评论收件箱」里新增「公开讨论」页，按页面列出所有公开讨论（直接从后端读取，所以还没同步进收件箱、或已经归档的评论也能管理）：

- 「在页面上隐藏 / 在页面上显示」：隐藏讨论开头的评论会连同整个讨论一起隐藏，会先提示有几条回复受影响；隐藏的内容不会再出现在任何访客的页面上。
- 「标为已解决 / 重新打开」：只对整个讨论。
- 「暂停新的公开评论 / 恢复公开评论」：按页面暂停，访客页面上会显示「作者暂停了新的公开评论。」
- 「隐藏这位访客的全部公开评论」：一次隐藏同一个编号在这个页面上的所有公开评论，用来处理刷屏。这些评论之后也不会因为别的操作重新出现：把其中一条从「不处理」改回别的状态、插件每小时补发一次你的设置时都一样；只有你逐条点「在页面上显示」才会重新显示。
- 「回复这个讨论 / 回复这条」：作者回复，所有访客都能看到。

这一页显示的是页面上现在的样子（从后端读取，包括一次隐藏整位访客、访客撤回的结果）；你刚做的操作还没被后端确认时，会显示你要的状态并加上「正在同步到后端…」。还需要处理的（访客看得到的）讨论排在前面，已隐藏的排在后面；讨论很多时只列出最近的一部分，并写明「只显示最近的 n 个讨论」。

在「评论与权限」里，公开评论的卡片标有「公开讨论」。你把它设为「不处理」时，它会同时在页面上隐藏（按钮写作「不处理（在页面上隐藏）」）；改回其他状态会重新显示，除非你另外点了「在页面上隐藏」。收件箱里的「已处理」不等于页面上的「已解决」。

只有你能改变访客看到的内容：任何 agent（包括评论助手）都不能隐藏、显示或标为已解决。评论助手对公开讨论的回复总是先成为草稿，要你确认后才会显示（「公开讨论里的 AI 回复要你确认后才会显示」），而且不能照抄任何仅自己可见或已隐藏的评论；访客在公开讨论里的回复不会唤醒评论助手。

### 公开评论的限制

| 项目 | 默认值 |
|---|---|
| 同一页面每天的公开评论和回复 | 100 条（被隐藏的不算） |
| 整个后端每小时的公开评论和回复 | 150 条 |
| 每位访客每天在同一页面开启的讨论 | 10 个 |
| 每个讨论的访客回复 | 40 条（被隐藏的不算） |
| 每个讨论的作者和助手回复 | 20 条 |
| 页面读取评论 | 每个地址每分钟 600 次 |
| 一次显示的讨论 | 最近 100 个，每个讨论最近 60 条消息 |

回复也计入上面「限制」一节的发帖次数。教室、办公室等大家共用一个出口地址的场合，所有人共用同一个地址的限制，可能需要调高 `postPerIpMinute` 和 `listPerIpMinute`；后端在代理后面但没有设置 `comments.trustedProxies` 时，面板会在公开警告旁边提示。

### 已有后端的升级

公开评论需要新的后端运行时（评论数据库从第 2 版升级到第 3 版）。升级会保留所有已有评论和回复，它们都保持「仅自己可见」。顺序很重要：

1. 先安装包含公开评论的新版插件（由你自己安装；请等这次的改动和评论助手的改动合并后再安装，之后不要再装回旧版插件）。
2. 备份数据库。
3. 在应用目录运行 `update-runtime`。
4. 按平时的方式重新启动或部署（新运行时第一次启动时升级数据库，失败会整体回滚）。
5. 确认 `node <应用>/board-app.mjs status --dir <应用>` 里有 `"publicThreads": 1`，并且收件箱仍在正常同步。

以本机的测试后端为例（在你自己的终端里运行，agent 不会替你做）：

```sh
node /Users/citrine/Projects/board-comment-page/app/board-app.mjs backup --dir /Users/citrine/Projects/board-comment-page/app --out /Users/citrine/Projects/board-comment-page/backups/before-public-threads.sqlite
paseo-board-app update-runtime --dir /Users/citrine/Projects/board-comment-page/app
# 然后按平时的方式重新启动这个应用，再检查：
node /Users/citrine/Projects/board-comment-page/app/board-app.mjs status --dir /Users/citrine/Projects/board-comment-page/app
```

升级后的数据库不能再用旧运行时启动；要退回旧运行时，只能恢复第 2 步的备份。部署在服务器上的后端用审核过的 `ssh plan` / `ssh deploy`，部署前会自动备份。
