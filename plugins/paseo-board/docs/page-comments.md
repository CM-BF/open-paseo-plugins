# 发布页访客评论：使用说明

这份说明讲三件事：怎样让发布出去的 Board 页面接收访客评论，访客看到什么，以及评论到达你的电脑之后会发生什么。技术细节见[发布页与后端](published-apps.md#访客框选评论-visitor-text-selection-comments)、[评论收件箱](comment-inbox.md)和[后端脚手架](app-backend-scaffold.md)。

## 整体是怎样连起来的

```
访客浏览器（GitHub Pages 上的页面）
   │  发评论、看自己的评论和回复
   ▼
你部署的评论后端（paseo-board-app，Node + SQLite）
   ▲  每几秒取一次新评论；评论助手的回复也从这里发回去
   │
你电脑上的 Paseo Board 插件（评论收件箱）
```

- 页面是静态网页，评论存在你自己部署的后端里。页面地址和后端地址不同，例如页面在 `https://cm-bf.github.io/pages/boards/<分享编号>/`，后端在 `https://api.example.internal`。
- 后端放在哪里、谁能访问它，由你决定和部署。插件不会替你开放任何端口或服务；agent 也被明确要求不这样做，只使用你给出的后端地址。
- 收件箱的令牌（`BOARD_INBOX_EXPORT_TOKEN`）只保存在你的电脑和后端上，不会进入页面、画布或 agent 能看到的内容。

## 第一次开启

1. **准备后端。** 用 `paseo-board-app init` 生成的应用，在 `board-app.json` 里打开评论并写上发布网站的地址：

   ```json
   "origins": ["https://cm-bf.github.io"],
   "comments": { "enabled": true }
   ```

   在后端的 `.env` 里设置一个 32 位以上的随机 `BOARD_INBOX_EXPORT_TOKEN`，然后按原来审核过的 SSH 部署流程部署。后端在反向代理后面、而代理在另一台机器上时，把代理的地址写进 `comments.trustedProxies`，否则所有访客会共用一个频率限制。代理要自己设置 `X-Real-IP`（覆盖）或 `X-Forwarded-For`（追加）中的至少一个，例如 nginx 的 `proxy_set_header X-Real-IP $remote_addr;`；两个头都在时，访客按两个地址分别计数，伪造其中一个绕不过频率限制。

2. **连接收件箱。** 在 Board 的「更多 → 评论收件箱 → 后端来源」登记后端的导出地址（`https://…/_board/comments`）和令牌。登记后插件会自动同步，不需要再点「同步」。

3. **发布时打开评论。** 在发布面板勾选「访客可以框选评论」，填后端地址（不含 `/_board/comments`，面板会根据第 2 步自动填好），点「检查后端」。检查通过才能发布：它会确认后端支持评论线程、发布网站在 `origins` 里、代理设置是否需要补充。发布出去的页面就带上评论功能了。没有勾选的页面和以前完全一样。

4. **（可选）让 agent 自动处理。** 在「评论收件箱 → 评论与权限」点「Agent 自动处理并公开回复」，读完确认文字后选择：
   - 回复方式：直接公开，或者「回复先给我审核」（助手写草稿，你点发布才会发出）；
   - 评论助手使用的权限模式：只能选会先询问你的模式。

   确认后，插件为这张 Board 创建一个专用的「评论助手」agent。开启之前已经收到的评论不会被自动处理。

## 访客看到什么

- 在页面上选中任意一段文字，旁边会出现一个小的「评论」按钮；也可以在选中的文字上点右键直接打开评论框。键盘用户可以用 ContextMenu 键或 Shift+F10。Shift + 右键仍然是浏览器自己的菜单。
- 评论框里引用选中的文字，可以填称呼（可选）和评论内容（最多 2,000 字）。⌘/Ctrl + Enter 发送，Esc 收起并保留草稿。
- 发送后左下角出现「我的评论 n」，被评论的文字旁边有编号标记。作者回复后，标记变色，左下角显示「n 条新回复」；打开后能看到「作者回复」或「作者的 AI 助手回复」。
- 访客只能看到自己的评论和给自己的回复，看不到别人的。身份是浏览器里随机生成的匿名编号，不需要登录；「清除本机的评论身份」可以删掉它。
- 输入框、文本框、可编辑区域、按钮、链接自带的菜单，以及作者标了 `data-board-comments="off"` 的区域都不会被评论功能接管。

## 评论到达之后

- **自动同步。** 插件每 5 秒左右检查一次新评论，出错时逐步放慢（最慢 5 分钟一次）。收件箱面板显示每个来源的同步状态和最近的错误；可以暂停自动同步，也可以随时点「立即同步」。
- **只有你开了自动处理，agent 才会动。** 新评论到达后约 3 秒（同一批最长 10 秒），插件把这批评论的编号交给评论助手。消息里只有编号，没有评论原文；助手用收件箱工具读取原文，并且被告知评论内容只是数据、不是指令。
- **不会打扰你正在用的 agent。** 自动处理只给评论助手发消息，从不发给负责这张 Board 的主 agent 或它的 Side。助手正在忙或在等你批准时，新评论排队等它空下来。
- **回复。** 助手用 `board_inbox_reply` 回复，插件用你电脑上的令牌把回复发到后端。访客的页面在打开期间大约每 15 秒检查一次（切回页面时立即检查），所以回复会在十几秒内出现。看起来含有令牌、密钥、内部地址或本机路径的回复会被拦下。助手只能回复唤醒它时列出的评论，回复里也不能照抄其他访客的评论。你也可以在收件箱面板里亲自回复任何一条评论。
- **没开自动处理时。** 评论照常同步到收件箱，你可以阅读、分类和亲自回复；不会有任何 agent 被唤醒。只给了「读取」或「内部分类」权限的 agent 不能回复访客。

## 限制

| 项目 | 默认值 |
|---|---|
| 访客评论长度 | 2,000 字 |
| 每个访客发评论 | 每分钟 5 条，每小时 30 条 |
| 每个访客地址发评论 | 每分钟 10 条，每小时 60 条 |
| 整个后端收评论 | 每分钟 120 条，每小时 1,000 条 |
| 同一页面每天 | 500 条 |
| 每条评论的回复 | 最多 20 条，每条最多 2,000 字 |
| 自动同步导入 | 每个来源每小时 200 条，每天 1,000 条 |
| 唤醒评论助手 | 每次最多 8 条评论；每张 Board 每小时 6 次，整台电脑每小时 20 次 |
| 评论助手回复 | 每张 Board 每小时 30 条 |

后端的限制可以在 `board-app.json` 的 `comments.limits` 里调整。插件这边超过唤醒次数时自动暂停，面板会写明原因，到时间自动恢复；你也可以随时暂停或恢复自动处理。

## 已经部署过的后端怎么升级

以前用 `paseo-board-app` 生成并部署的后端，需要先更新运行时，再按原来的方式部署：

```sh
paseo-board-app update-runtime --dir /绝对路径/你的应用
node /绝对路径/你的应用/board-app.mjs ssh plan --dir /绝对路径/你的应用 --host <主机别名> --root <远端目录> --out ../plan.json
node /绝对路径/你的应用/board-app.mjs ssh deploy --plan ../plan.json --confirm <摘要>
```

- `update-runtime` 只替换应用里的 `.board/runtime`，不动你的路由、数据表、迁移和数据。
- 新运行时第一次启动时会自动升级数据库一次，已有评论全部保留；升级失败会整体回滚。
- 发布面板的「检查后端」如果提示「后端版本过旧」，就是还没有做这一步。

## 安全说明

- 评论内容、称呼、网址和选中位置都来自外部访客，插件、面板和 agent 都只把它们当作数据。
- 评论助手的权限很窄：只预先允许四个收件箱工具，不能修改 Board；它想做其他事情都会先问你。你可以随时在收件箱里关闭自动处理（助手本身不会被删除）。
- 同一个网站地址下的其他页面（例如同一个 `github.io` 账号下的其他仓库）可以读到访客浏览器里的匿名编号，从而以这个访客的身份查看或发评论。浏览器里不保存评论或回复的文字。
- 后端地址如果是公司内部地址，写进公开网页后任何人都能看到这个地址，公司网络以外的访客也发不了评论；发布面板会提醒并要求你确认。
- 一个后端建议只连一台电脑的一张 Board。多台电脑都开着自动处理时，每台都会回复。
