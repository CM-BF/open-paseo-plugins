## Behavior

Users can add comments at several positions to a pending list, edit or remove them, and send the reviewed list together to one destination. Each comment retains its text, frozen location and available screenshot. Reload preserves the list. One submission creates one ordered interaction and delivery, with a shared result and numbered locations. Ordinary drafts are included only when explicitly staged; immediate single sends and replies to existing discussions remain available. Fresh authored `board.ask` calls resolve `queued` after local persistence, without implying delivery.

A send freezes the exact ordered revisions and destination. Unknown outcomes retain the original intent and payload; reconciliation clears only submitted revisions, preserving later edits. Cross-tab preparation uses Web Locks and refuses a queue changed while waiting. Failed local persistence prevents sending. Limits are 20 comments, 24,000 combined text characters and 6,000,000 PNG base64 characters. Browsers without Web Locks retain single-comment sending.

The authored Comment failure was reproduced on the baseline: an `HTMLParagraphElement` reached native `postMessage` and raised `DataCloneError`. Connected Elements and `{target: element}` now become bounded plain reference metadata; invalid references are rejected and failed requests release their pending slots.

Board-originated visual work now receives consistent guidance to use the existing shared main canvas from its first reply. Main/Side selects the receiving agent. Explicit user destinations take precedence, text-only replies remain valid, unrelated chat is unaffected, and existing saved delivery prompts remain immutable.
