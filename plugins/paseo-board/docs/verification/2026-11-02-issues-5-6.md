# Issues #5 and #6: root-patch recovery and sticky screenshots

Runtime commit `80ac1dd8677b25cf195505180c4851c1ab899c4c` fixes [issue #5](https://github.com/CM-BF/open-paseo-plugins/issues/5) and [issue #6](https://github.com/CM-BF/open-paseo-plugins/issues/6). It passed clean-source verification, was backed up and installed on the primary local daemon, and passed actual Web UI acceptance. The remote Linux host described in issue #5 has **not** been upgraded or tested in this task. The dedicated temporary acceptance Board has been removed and the original seven Boards were verified through the real application. The repair is delivered through a feature PR; main remains subject to explicit merge approval.

## Resulting behavior

For fragment documents, `body` append/prepend patches now describe the beginning/end of authored content. Existing persisted journals, including later patches, materialize for export, release preview and editable copy without deleting history or replacing the Board. Destructive root replace/remove requests are rejected before persistence, including aliases that resolve to the actual document root. Full-document head/body attributes remain supported. Fragment head/html insertion remains unsupported; runtime-generated targets still work live but can produce an explicit static-replay limitation. The server does not execute authored JavaScript to invent missing targets.

Screenshot planning now calculates directional shadow paint bounds from each layer's offset, spread and blur. A nearby sticky element is included only when its paint can affect the crop. Proven undisplaced sticky geometry can be reproduced in the clone while preserving its stacking behavior; validated clone scrollbars no longer introduce pixels absent from the live view. The live DOM, scroll, focus and controls are not changed for capture. Unsupported genuinely constrained sticky geometry, transforms, ambiguous insets or scrollbar gutters still receive an explicit screenshot failure while retaining the geometric reference.

## Retained failures and interpretation

- Frozen original source reproduces the reported body replay failure and sticky halo/point failures. The first new store-test draft omitted required revision fields; those schema failures are retained separately and do not count as root-replay evidence. Corrected old-source cases reached the intended defect before the fixed source passed.
- A nested sticky fixture initially differed because the foreignObject clone painted an overlay scrollbar absent from the live view. The fix affects validated clone rendering only; it does not hide a real live gutter or change live scroll.
- A proposed end-inset rejection case was actually outside the selected crop and not constrained. The corrected fixture asserts actual live geometry, crop participation and displacement before expecting success or refusal.
- The text-shadow comparison exposed antialiasing differences. Painted bounds and ink geometry matched; the case now has specific coverage/position/error checks. Non-text tolerances were not broadened to conceal the failure.
- An old animation rejection test sometimes finished between real animation frames. It now synchronizes a real frame after planning and before serialization, asserts that the frame advanced, and verifies rejection of that actual in-capture visible change.
- Actual-host release-menu attempts timed out after earlier screenshot/reload checks had passed. Recorded input diagnostics showed the More-button click but did not establish a specific product defect. The driver now observes stable menu geometry after pointer movement and reveals the target instantly before one genuine click. The remaining preview/ZIP steps then passed. Accepted source patches and already-passed stages were reconciled by their original IDs; they were not recreated or blindly retried.
- The first final-fixture cleanup gate stopped before disabling the plugin because a periodic extraction checkpoint changed the file hash without changing its revision, content or history. This was a cleanup-gate assumption, not evidence of a product defect. The reviewed cleanup revision permits only the known `board.extraction` metadata shape while comparing every other envelope field; it pins raw bytes again after confirmed pool shutdown and requires byte-identical files throughout the move. The original failure is retained alongside the later completed cleanup and reconciliation receipts.

- The immediate post-enable socket check ran before `bridge.sock` existed, after the scoped move and plugin enable had already completed. The script stopped without a second mutation. Subsequent read-only reconciliation found the socket ready and verified the exact remaining envelopes, artifacts, workers and RPC inventory; the original failed receipt is unchanged. No repeated disable/enable or move was required.

The final receipt retains prior failure diagnostics and script-revision provenance alongside the successful result. A passing retry of the remaining stages is not evidence that an unproven product root cause was fixed.
