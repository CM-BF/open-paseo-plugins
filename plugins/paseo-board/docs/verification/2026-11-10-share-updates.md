# 分享页跟随 Board 更新：固定链接与一键更新

2026-11-10，运行版本 `0d9faeba31f43224264010a32cef0d0eb6d787d6`。同一张 Board 改动后，由人点一次确认，把新版本发布到已经分享的同一个链接；旧版本保留可回看。发布版本本身仍不可变，agent 工具没有发布入口。

## 行为

- 分享链接（series）由 Board、GitHub 主机、仓库和 key 确定。新发布使用客户端生成的 `s` + 20 位十六进制 key：固定目录 `boards/<key>/`，每个版本另存 `boards/<key>/v/<releaseHex>/`。
- 功能之前已发布的分支式站点（`boards/<releaseHex>/`）在第一次更新时被沿用：该目录成为固定目录，原版本写入 `v/<releaseHex>/`，链接不变。
- github.com 上由工作流部署的新站点，固定链接是站点根目录，生成的 workflow 文本不变，这一模式暂无线上旧版本存档，旧版本在本机预览或下载。
- “有改动还没发布”只比较页面源码（`documentVersion` 与补丁数），数据写入和 Board 改名不算。
- 更新沿用上次发布的标题、主题、联网方式、API 来源和公开数据，保存在私有的 `releases/<releaseId>.settings.json`。此前的发布版本没有这份记录，需要先在面板生成一次。
- 更新面板自动生成并预览新版本，只有一次“确认并更新分享页”会发布。

## 安全规则

固定目录只接受空目录或本 Board 已发布版本的逐字节内容；只能向前更新，旧请求（包括恢复的请求）不能覆盖更新的版本；同一分享链接合并前只允许一个进行中的任务，合并后的未核验站点（公司 SSO）不阻塞下一次更新；内容没有变化时不创建 PR。

## 验收

在分支提交上：TypeScript 通过；653 项源码测试（643 项并发 + inbox-sync 10 项串行）通过；发布页 13 项、发布界面 24 项、工具栏 3 项、宿主界面 38 项通过；worker 与 client 两次重建逐字节一致。三路独立评审提出的 11 项问题均已核实并修复，原评审、设计与修复记录保存在私有目录。

本机安装：备份后替换 27 个跟踪文件，Board 重载一次，daemon 未重启。安装脚本在最后一步判失败，原因是安装期间新建了专用测试 Board，Board 清单与预期相差一项；只读核对确认全部跟踪文件与提交一致、旧 worker 退出、新 worker 运行、原 18 张 Board 全部保留、唯一新增是该测试 Board。失败回执与核对记录都保留。

## 未验证与限制

- “沿用已分享的旧链接”、公司 GitHub Enterprise（含 SSO）只由模拟 GitHub 的测试覆盖，没有在真实站点上运行。
- 普通访客可能因 CDN 缓存晚几分钟看到新版本；访客本地保存的状态按版本隔离，更新后重新开始。
- Board 数据实时到分享页（经后端）不在本次范围。
