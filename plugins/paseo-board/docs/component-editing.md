# Direct component editing

This change extends the existing component inspector into an editing surface. The user can select an existing element, move it into another container, copy its structure, or edit text. Agent-authored HTML, CSS, scripts and existing publishing APIs remain available without a required component model.

Direct gestures let the user right-click a selected component to reference it, drag its body to move it, and double-click its text to edit at that position. The caret and draft retain the original typography and wrapping. The [October 31 gesture record](verification/2026-10-31-direct-gestures.md) describes that historical runtime's checks and its incomplete native gesture acceptance; earlier native acceptance belongs to the [feedback fixes](verification/2026-10-31-component-edit-polish.md) and [initial implementation](verification/2026-10-31-component-editing.md). These changes were subsequently delivered through [merged PR #4](https://github.com/CM-BF/open-paseo-plugins/pull/4).

The pointer insertion and animated drag preview described below are the current branch's candidate feature. They have passed the focused and existing source-browser regressions described below, but are not yet installed or accepted on the primary daemon. Historical verification records do not establish acceptance of this candidate; its delivery status is tracked in [PROGRESS.md](../PROGRESS.md).

## Interaction

- Hold Command+Shift on macOS, or Control+Shift on Windows/Linux, to preview the component under the pointer. Click to select it. Editable inputs keep their normal keyboard and selection behavior.
- Right-click inside the selected component to open a blank message composer with the whole component reference. The frozen selector, component binding, ancestor information, document/canvas revision and screenshot accompany the message when the user sends it. The agent is explicitly told to read the current authored target before editing; a placement fingerprint is not editing authority. Right-click outside the selection retains the ordinary point-reference behavior, and native editors retain their context menus.
- Drag the selected component body to move it. Movement of at least 6 CSS pixels starts a structural drag with a static image of the selected content. An edge or actual gap selects insertion between siblings; the center of an eligible container selects nesting inside it. A target outline, insertion line and bounded layout copy show the proposed placement. Tab/Shift+Tab change the containment level, and direction keys explicitly choose the position. A small movement remains a click. Escape, focus loss, pointer cancellation or a changed source/target cancels the gesture.
- Selection also opens a compact toolbar; ancestors, children and additional operations expand on demand. Ordinary clicks inside the selected parent keep that parent selected for direct gestures. Hold Command/Control+Shift while clicking to deliberately select a nested child. The move handle remains available as an alternative.
- Cut records a pending move without removing the source. Selecting a destination and pasting prepares the move. Copy/paste prepares a structural duplicate. The clipboard is internal to the current Board; it does not read or write the operating-system clipboard.
- Double-click the actual words within a selected component to edit that exact text run in place. The **改字** toolbar action remains available. The isolated editor changes one direct text run while preserving sibling controls and inline markup. Click another run or use the compact run selector; finish or cancel a changed run before switching. **完成文字** or Command/Control+Enter prepares the draft for host Save. Escape cancels; neither shortcut interrupts IME composition. Padding and graphics do not guess another text target; native input controls retain normal selection and typing.
- The ordinary Save card contains only the operation summary and Save/Cancel actions. Pending text remains visible and read-only at its source position. A rejected or uncertain save also exposes a read-only copyable draft for recovery.
- Text paste inserts plain text; ordinary text selection, spaces, nonbreaking spaces, newlines and undo/redo stay available. Rich-text formatting and drops into the draft are disabled. This text clipboard behavior is separate from the internal structural component clipboard.
- Drop, paste and text editing prepare a change. A compact host-owned Save/Cancel surface commits it; an authored iframe can propose an edit but cannot grant itself persistent write authority. This is the normal editing commit, not an agent-message or modal permission flow.
- Move/copy proposals show a static layout preview built from isolated visual copies. The original nodes, input values and listeners stay in place until Save. The preview can be compared with the original; cancellation removes it. Dynamic/custom content may appear as a marked placeholder, and bounded previews explicitly report when content is too complex to display rather than claiming a complete result.

## Pointer insertion and drag preview

Drag toward a sibling's leading or trailing edge to insert before or after it. Actual gaps between containers also accept a sibling insertion, including direct children of `body`; an extra grouping wrapper is unnecessary. The indicator follows the layout: horizontal lines for vertical stacks, vertical lines for horizontal rows, and row-boundary lines for ordinary wrapped/grid rows. RTL and reversed flex directions are interpreted from the container's flow. Clipped or offscreen edges do not become artificial visible drop zones.

Move into the center of a container to put the selected component inside it. Text explaining an otherwise empty container does not turn its central blank area into an insertion after that paragraph. When dragging a container, automatic sibling gaps refer to other containers; direct leaf-to-leaf reordering remains available. A same-parent card's center targets that card rather than a heading or control within it. **Tab** moves outward through the actual ancestor chain and **Shift+Tab** moves inward; selecting an outer card automatically does not reorder that chain. **Up/Down** choose before/after, and **Left/Right** choose prepend/append. The chosen line and operation label are the placement to review before releasing.

While the pointer is held, siblings in an inert visual copy make room for a translucent placeholder. Authored nodes, inline styles, inputs, event listeners and embedded frames remain untouched. Hit testing uses the original geometry rather than the moving copies, avoiding a destination that moves away from the pointer. Releasing the pointer stages the existing host Save/Cancel review; it does not commit a move. **Save changes** applies the semantic move to the original node, **Cancel** keeps the original layout, and **Esc** during dragging removes the preview without a proposal. An already-adjacent placement is a no-op. A source or destination replaced under the same ID invalidates the gesture instead of redirecting it.

The component toolbar's **•••** menu contains **拖动让位动画**. It defaults to on. Turning it off preserves the static placement preview and insertion line while removing motion; the system's reduced-motion preference also suppresses the movement animation. This setting survives selecting other components in the same canvas frame. It is not a permanent Board setting: rebuilding the frame or reloading the Board restores the default. It is not written to authored state or exported content.

The drag copy is limited to 1,800 visited nodes, a 100ms copy budget and 1.5 million copied characters. Embedded media can use inert placeholders rather than running another application instance. If copying exceeds its limits, the UI withdraws the copy and explicitly keeps only the insertion indicator; it does not promise a complete animated layout. If target geometry or structural identity cannot be confirmed, the pending drop target and its indicators are cleared, so releasing the pointer cannot reuse an earlier location. These limits are separate from the post-drop Save preview. Pointer updates are coalesced per frame, and scrolling or resizing refreshes the geometry from the original canvas.

Automatic dragging refuses layouts whose visual order cannot be represented reliably by a normal DOM insertion: absolute/fixed positioning, non-horizontal writing modes, reverse flex wrapping, custom flex item `order`, explicit grid placement, or a destination with more than 160 direct children. Managed disclosure parts also retain their structural guards; move the complete container rather than splitting its heading/body. The inspector reports the limitation and offers the existing explicit cut/paste placement workflow where that structure is supported. Agents can still edit authored CSS and layout code. Paragraphs, headings, controls and other non-container elements cannot accept a nested component through the drag controls.

## Text draft boundaries

The original authored element is never made contenteditable. A bounded visual copy supplies the editable text run, following nested scrolling and resizing without replacing the active editor or its caret. An inline source retains its containing formatting context so its baseline and initial wrapping remain aligned. The selected run can grow or wrap in the copy; the complete original page does not reflow before Save.

The original Text node, child index, previous value, source identity and displayed canvas base stay fixed throughout the edit. A replaced node is not accepted merely because it contains the same words. Changes to the source or its copied inline surroundings withdraw the stale preview and preserve a read-only draft. If the original position is hidden or unavailable, a small recovery area reveals that draft; its own scrolling does not move the Board. Nothing is automatically resubmitted after a conflict.

Simple SVG text retains the SVG semantic target and uses a glyph-position editing copy. Complex transforms, text paths, multi-position tspans, gradient/pattern paint and arbitrary graphics or layered backgrounds are not established as visually exact. Copies also have node, time and byte limits; unsupported or excessive structures can refuse direct editing. These limits do not restrict what agents may author or publish.

## Durable edits

The host freezes the displayed canvas base, operation and event identity. The authenticated user RPC runs through the same bounded worker pool and durable transaction machinery as other Board writes. A concurrent canvas change rejects the old base; it never silently adopts a fresh revision and overwrites the intervening change. An uncertain acknowledgement retries the exact original request.

`board.edit` returns an event-scoped `applied` or `rejected` result. A known refusal releases cancellation and keeps a text draft available for copying. Generic host errors, worker exits and I/O failures do not prove that a write failed: they remain uncertain and retry the original event, base and payload. This distinction does not depend on matching an English error message.

An uncertain save survives Board-view navigation/remount within the current host JavaScript session. It is not a disk-backed outbox across a complete app/page restart; restarting does not automatically resend it. The server's committed edit and receipt are durable independently.

Additive move, copy and text patches are replayed by both the authored-source reader and the live frame. A move relocates the existing DOM node rather than serializing and recreating it. Unrelated inputs, listeners and runtime state remain in place. Text changes carry an expected previous value. Root replacement, containment cycles and ambiguous targets are refused before committing.

Source and destination identities must resolve reliably in the persisted authored document. Unique authored IDs provide a stable target; anonymous elements need stronger structural evidence. Text changes in a live counter are not used as the identity of its whole containing component. A node created solely by script cannot be represented as an authored-source edit automatically; the UI reports this limitation instead of claiming a durable change. Its author can still change it with code or data.

Structural signatures include actual parent relationships, tag/ID, role, name and type, with a 2,000-element bound. Anonymous elements additionally compare parsed authored content (up to 240,000 characters), preserving their outer attributes, anonymous text and containment. A globally unique ID descendant with unchanged structure can carry live text/state without making its anonymous container a different target. Duplicate identities, changed anonymous surroundings and changed parent relationships remain conflicts. The server and frame replay use the same boundary; a copy still comes from saved authored HTML. These are bounds on direct editing, not on what agents may author.

Copying duplicates structure and remaps internal IDs/references. It does not duplicate JavaScript closures, attached event listeners, or arbitrary library instance state, and does not rerun copied scripts. CSS ID selectors are not rewritten, whether they come from an external stylesheet or a `<style>` element inside the copied component. A selector such as `#original-card .value` continues to target the original ID, so the copy may need author changes to preserve that styling. Moving an existing component and duplicating its application behavior are different operations.

A marker on an anonymous component follows that same live DOM node when the component moves within the current frame. After reopening the Board, that in-memory identity is gone. The existing patch journal does not provide enough revision evidence to prove that an old positional selector identifies the moved component, so cold recovery keeps the original frozen reference and reports an unavailable location or a verified ancestor rather than guessing. The captured anchor is never rewritten to suggest a new location. Unique authored IDs can continue to recover through the existing identity checks. This release does not migrate journal revisions or claim durable marker relocation for anonymous components.

Moves use the browser's state-preserving move operation when available, with an ordinary same-document move fallback that restores focused inputs and their caret. Older browsers may reset some embedded media/frame state on that fallback even though the element and its listeners are retained.

The November 3 source candidate passed 13 focused drag checks, the complete 111-check canvas suite (which includes those drag checks), 13 component-edit host checks and 8 static-release checks. Trusted browser input covers before/after edges, actual gaps in vertical stacks and direct-body containers, flex rows, grid row boundaries, central nesting, both hierarchy-key directions, Save/Cancel and guarded refusals. Accepted moves use the actual server source preparer. Checks retain node identity, input/caret, listeners and iframe heap, verify rendered intermediate animation positions, require the actual iframe's reduced-motion media condition, and cover 420px layout plus cold semantic replay.

The target-budget regression starts with a valid small target, then enters an original container containing 2,131 descendants and 31 direct children. The old target and indicators must disappear; Tab and ArrowRight without another pointer move cannot revive them. Releasing stages no edit, raises no browser exception and leaves the source intact. This distinguishes failure to identify a destination from the separate visual-copy fallback.

The private evidence is pinned by `focused-1793736248131070000/receipt.json`; retained earlier failures and remaining work are recorded in [PROGRESS.md](../PROGRESS.md). These tests adapt the host approval/transport boundary. Exact-commit clean-build verification, installation and an actual primary-daemon Web walkthrough remain pending; no live delivery is claimed here.
