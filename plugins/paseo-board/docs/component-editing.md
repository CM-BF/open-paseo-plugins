# Direct component editing

This change extends the existing component inspector into an editing surface. The user can select an existing element, move it into another container, copy its structure, or edit text. Agent-authored HTML, CSS, scripts and existing publishing APIs remain available without a required component model.

The locally installed PR build includes source-position text editing: the caret and draft appear over the original words, with matching typography and wrapping. Its [verification record](verification/2026-10-31-inline-text.md) covers clean automated checks and installation; native UI acceptance of this iteration was unavailable because the running app exposed no usable window. Earlier native acceptance belongs to the [feedback fixes](verification/2026-10-31-component-edit-polish.md) and [initial implementation](verification/2026-10-31-component-editing.md). Delivery remains on draft PR #4; main requires explicit merge approval.

## Interaction

- Hold Command+Shift on macOS, or Control+Shift on Windows/Linux, to preview the component under the pointer. Click to select it. Editable inputs keep their normal keyboard and selection behavior.
- Selection opens a compact toolbar; ancestors, children and additional operations expand on demand. Its move handle starts a structural drag with a static image of the selected content. A target outline and insertion indicator show the destination; Tab/Shift+Tab change its containment level, and direction keys change the insertion position.
- Cut records a pending move without removing the source. Selecting a destination and pasting prepares the move. Copy/paste prepares a structural duplicate. The clipboard is internal to the current Board; it does not read or write the operating-system clipboard.
- Select a component and choose **改字** to place the caret directly over its text. The isolated editor changes one direct text run while preserving sibling controls and inline markup. Click another run or use the compact run selector; finish or cancel a changed run before switching. **完成文字** or Command/Control+Enter prepares the draft for host Save. Escape cancels; neither shortcut interrupts IME composition.
- The ordinary Save card contains only the operation summary and Save/Cancel actions. Pending text remains visible and read-only at its source position. A rejected or uncertain save also exposes a read-only copyable draft for recovery.
- Text paste inserts plain text; ordinary text selection, spaces, nonbreaking spaces, newlines and undo/redo stay available. Rich-text formatting and drops into the draft are disabled. This text clipboard behavior is separate from the internal structural component clipboard.
- Drop, paste and text editing prepare a change. A compact host-owned Save/Cancel surface commits it; an authored iframe can propose an edit but cannot grant itself persistent write authority. This is the normal editing commit, not an agent-message or modal permission flow.
- Move/copy proposals show a static layout preview built from isolated visual copies. The original nodes, input values and listeners stay in place until Save. The preview can be compared with the original; cancellation removes it. Dynamic/custom content may appear as a marked placeholder, and bounded previews explicitly report when content is too complex to display rather than claiming a complete result.

## Text draft boundaries

The original authored element is never made contenteditable. A bounded visual copy supplies the editable text run, following nested scrolling and resizing without replacing the active editor or its caret. An inline source retains its containing formatting context so its baseline and initial wrapping remain aligned. The selected run can grow or wrap in the copy; the complete original page does not reflow before Save.

The original Text node, child index, previous value, source identity and displayed canvas base stay fixed throughout the edit. A replaced node is not accepted merely because it contains the same words. Changes to the source or its copied inline surroundings withdraw the stale preview and preserve a read-only draft. If the original position is hidden or unavailable, a small recovery area reveals that draft; its own scrolling does not move the Board. Nothing is automatically resubmitted after a conflict.

Simple SVG text retains the SVG semantic target and uses a glyph-position editing copy. Complex transforms, text paths, multi-position tspans, gradient/pattern paint and arbitrary graphics or layered backgrounds are not established as visually exact. Copies also have node, time and byte limits; unsupported or excessive structures can refuse direct editing. These limits do not restrict what agents may author or publish.

## Durable edits

The host freezes the displayed canvas base, operation and event identity. The authenticated user RPC runs through the same bounded worker pool and durable transaction machinery as other Board writes. A concurrent canvas change rejects the old base; it never silently adopts a fresh revision and overwrites the intervening change. An uncertain acknowledgement retries the exact original request.

`board.edit` returns an event-scoped `applied` or `rejected` result. A known refusal releases cancellation and keeps a text draft available for copying. Generic host errors, worker exits and I/O failures do not prove that a write failed: they remain uncertain and retry the original event, base and payload. This distinction does not depend on matching an English error message.

An uncertain save survives Board-view navigation/remount within the current host JavaScript session. It is not a disk-backed outbox across a complete app/page restart; restarting does not automatically resend it. The server's committed edit and receipt are durable independently.

Additive move, copy and text patches are replayed by both the authored-source reader and the live frame. A move relocates the existing DOM node rather than serializing and recreating it. Unrelated inputs, listeners and runtime state remain in place. Text changes carry an expected previous value. Root replacement, containment cycles and ambiguous targets are refused before committing.

Source and destination identities must resolve reliably in the persisted authored document. Unique authored IDs provide a stable target; anonymous elements need stronger structural evidence. Text changes in a live counter are not used as the identity of its whole containing component. A node created solely by script cannot be represented as an authored-source edit automatically; the UI reports this limitation instead of claiming a durable change. Its author can still change it with code or data.

Structural signatures include actual parent relationships, tag/ID, role, name and type, with a 2,000-element bound. Anonymous elements additionally compare parsed authored content (up to 240,000 characters), preserving their outer attributes, anonymous text and containment. A globally unique ID descendant with unchanged structure can carry live text/state without making its anonymous container a different target. Duplicate identities, changed anonymous surroundings and changed parent relationships remain conflicts. The server and frame replay use the same boundary; a copy still comes from saved authored HTML. These are bounds on direct editing, not on what agents may author.

Copying duplicates structure and remaps internal IDs/references. It does not duplicate JavaScript closures, attached event listeners, or arbitrary library instance state, and does not rerun copied scripts. CSS ID selectors are not rewritten, whether they come from an external stylesheet or a `<style>` element inside the copied component. A selector such as `#original-card .value` continues to target the original ID, so the copy may need author changes to preserve that styling. Moving an existing component and duplicating its application behavior are different operations.

A marker on an anonymous component follows that same live DOM node when the component moves within the current frame. After reopening the Board, that in-memory identity is gone. The existing patch journal does not provide enough revision evidence to prove that an old positional selector identifies the moved component, so cold recovery keeps the original frozen reference and reports an unavailable location or a verified ancestor rather than guessing. The captured anchor is never rewritten to suggest a new location. Unique authored IDs can continue to recover through the existing identity checks. This release does not migrate journal revisions or claim durable marker relocation for anonymous components.

Moves use the browser's state-preserving move operation when available, with an ordinary same-document move fallback that restores focused inputs and their caret. Older browsers may reset some embedded media/frame state on that fallback even though the element and its listeners are retained.
