## 接续自行发现并修复的遗漏

1. resume 不能只按独立调用 key 匹配。现把完整调用前缀纳入匹配，覆盖重排、删除、重复调用和跨 resume 链的不同前缀。明确失败会结束本次后续缓存复用；被停止切断的在途调用重跑后仍可复用后续已完成结果。
2. 旧格式日志在跨链合并时先保留调用位置，再按 key 分组，避免把祖先的同一槽位重复追加成不存在的缓存调用。
3. worktree 重试的 `pendingBranch` 按实际 attempt 调用 ID 记录，避免创建中断后的恢复查错分支。

各新增回归都先在修复前失败，再修复通过。同步更正前次文档中“失败不结束后续缓存”和“同脚本所有 pipeline 总能全缓存”的过度承诺。

## 仍有差异和未验证范围

- 同时可见原生 Workflow 时，只用指引要求优先选插件，未隐藏原生工具。
- Paseo 的通知仍通过 user_message 运输，插件加了明确自动事件边界；原生内部角色、回合内通知合并和折叠机制不可直接复用。
- 结构化输出使用跨 provider 的 JSON 提取与纠正，子任务仍可能拒绝或输出额外格式；不能承诺模型输出完全一致。
- 工具默认预批准、预算仅核算插件可见子 agent、resume 新 run ID、暂停/限流等待、部分细节校验、进度信息和保存工作流 UI 等仍有差异。逐项见 PARITY.md。
- 当前自动卡死重试最多3次尝试，未完全复刻原生的全部重试/退避分支。
- 禁止子 agent 再委派有工具入口移除和提示约束，不是宿主对所有委派工具的强制沙箱。
- 没有重新运行原审查的完整性/计划阶段，没有重跑已完成的数百个审查 agent。
