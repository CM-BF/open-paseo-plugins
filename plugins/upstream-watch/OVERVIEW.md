上游更新记录每个插件参考的 GitHub 项目、功能目录或 fork 上游，定期检查变化，并让你一键创建负责适配的 agent。一个插件可以关联多个上游，每条关联保留已采用或已处理的 commit。

也可以选择“只提出移植建议”：登记核心功能、上游和本地路径、已移植或缺失状态，每次扫描给出固定版本源码链接和待核对变化。Cindy 提供一份可编辑的核心清单，使用官方仓库和已采用基线。状态是登记的评估，不是自动验收结论；无新差异时仍保留缺失项。可以手动“开建议 agent”，也可为这条关联开启定期自动建议。新上游版本、功能清单或本地 Git 提交改变时，使用所选工作区和模型只读审查一次；不执行移植或推进基线。Codex 建议任务使用只读文件沙箱；其他模型保留宿主原生权限。

在“发现来源”中读取插件的 UPSTREAM.json、SOURCE.json 和 Git remote 候选，确认开发目录与基线后添加；也可以手动登记仓库、分支、关注文件或目录。默认每天只读比对 GitHub，不调用模型；单独启用的自动建议会使用所选模型。变化显示在侧栏数量与列表中，直到你明确标记已处理或跳过。

工作区选择器支持按名称或路径搜索，长列表在限定高度内滚动。可以选择已有 Workspace，也可以选 Project，在它现有的目录中新建 Workspace；此操作不新建 Git 分支，也不启动 agent。

“开更新 agent”使用你选定的工作区、模型和原生权限设置，带上固定版本、相关提交、路径及适配说明。工作区必须包含插件开发目录。创建 agent 不会推进已处理基线。重复点击共用任务，未知创建结果保留原身份供核对后重试。

需要 Paseo 0.13.2；自动建议还需要本机 Paseo CLI、有效 Git 源码目录、工作区和模型。GitHub 访问优先使用本机 gh 的已有登录，否则匿名访问公开仓库；失败和限流会显示原因，并保留上次成功结果。关注路径为文件或目录前缀，不使用 glob。差异截断、历史分叉等情况显示需要核对。

提醒是应用内徽标和持久化列表。不发送外部通知。直接升级安装源仍使用 Paseo 原生插件更新功能。本插件不会自动执行上游脚本、安装、发布或合并变更。
