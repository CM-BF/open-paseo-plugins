These are source and build checks, not installed visual acceptance; clean production export, reload and live verification remain separate gates.

Task ownership comes from a durable native child-ID index and a verified workspace/cwd, never a status or label guess. Release changes future follow-up responsibility while retaining the creating companion's pill. The pill uses the new optional per-agent header slot; an older host does not receive a substitute workspace-toolbar badge. The service persists operation IDs and payload fingerprints for queue/resume/edit/withdraw. An old host without atomic idle-send admission keeps the task unsent and paused; the card shows the exact upgrade blocker, resumes the same task without resending its objective, or requests real cancellation.

Known UI differences remain explicit: private task cards replace an actual successful, schema-checked delegation tool row because the public transformer lacks Cindy's whole-turn introduction anchor; native task result text is selectable plain text because the SDK has no equivalent rich-answer renderer; group cards retain the original Markdown. PR chips await a verified PR catalog. Owner-pill placement, current-agent navigation, task actions, original colors/spacing and compact behavior require installed acceptance after the host APIs are integrated. Native task completion is not human acceptance and does not release ownership.

The recovery follow-up has 94 passing offline frontend tests. Task, discussion, work-step and organizer UI distinguish known-unsent input from unknown admission and unconfirmed stopping, in English and Chinese. Missing provider-safe admission remains an explicit blocker even after an SDK upgrade; the UI does not promise that updating Paseo enables execution. These recovery changes passed the integrated build and still await installed acceptance.
