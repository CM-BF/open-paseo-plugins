# Personal skill adapter

The source primitives and exact upstream hashes are recorded in `./vendor/skills/SOURCE.json` at Cindy commit `5f0b5f42b46969c3ac21b0cd798a07e36b46e8fd`.

`companion-skills.ts` is Paseo integration code. Structured saves are validated and rendered by the original `saveBotSkill` in private staging. Parsing, query indexing, streaming metadata, caching and bounded native projection use the extracted original implementations. The local plugin manifest uses the original `ensureLayout` JSON fields and formatting.

Adaptation: writes publish with an atomic file/directory rename under the companion's existing home. Each immutable operation ID has a prepared/completed record under `skill-operations/<companion>/`, serialized with profile mutations by `CompanionStore.transaction`. A SHA-256 revision hashes the enabled state and exact source digest; retries reconcile only their exact before/after bytes. Completed retries return their historical receipt without overwriting later edits. Deletion first renames the complete folder into its operation-owned trash and records completion before disposing it. Scripts, references and executable bits survive enabled/disabled moves. Publication rechecks native authority and source revision after preparation and immediately before rename. This does not claim filesystem compare-and-swap against arbitrary noncooperating external editors.

The API checks companion existence and deletion intent, refuses symbolic links along its entrypoint/generated paths, and retains the original complete skill library. Full-source management RPC has a 1 MiB response/input bound; larger hand-authored sources remain on disk, searchable, projectable and enableable/disableable. `skills.inspect` streams the source digest with a bounded buffer and exposes revision, size and state without returning its content; public management therefore remains available for large files. The original 64 KiB body bound applies to authored writes. No global skill catalog is written. UI query responses omit native file paths; only the authorized native session query exposes paths within its own library.

Reading an individual document and querying a library preserve original source bytes. Read-only queries explicitly disable the upstream legacy-header migration and use `CompanionStore.withSnapshot` so they do not rewrite the main state journal. Trusted native projection retains bounded legacy-header migration. All hold the existing serialization boundary. A save receipt explicitly reports native loading as pending: projection construction is not evidence that a provider loaded or followed a skill.

Each cached query-index build carries a catalog revision. Continuations submit that revision, so a rebuilt index rejects the old page instead of mixing two library snapshots. This catalog revision is independent from an individual source document's edit revision. The original runtime cache similarly carries a source epoch and enabled count with its projection; the epoch is a conservative rebuild marker, not a full-library content hash or evidence of instruction use. An empty enabled library supplies explicit empty native mounts. Only the bounded selected profile IDs are classified against both personal shelves; disabled local skills are not mistaken for external selections.

`companion-skills-projection.ts` inspects exact directory-entry spelling because case-insensitive filesystems can make `stat('SKILL.md')` resolve a lowercase `skill.md`. A lowercase entry forces the original discovery projection, whose catalog references the original source and resource directory. Empty shelves retain an empty direct root and never mount a stale discovery directory. The upstream projector remains byte-identical.

`service.ts` connects the adapter to public skills RPC and the admitted scoped MCP path. `companion-skills-tools.ts` adapts the original list/save tools and aliases, adds exact-revision reads and operation receipts, and binds access to the actual durable native session. Canonical/routine roles may save; group/plan roles remain read-only. Legacy memory-only credentials do not gain these tools, and disabling Memory does not disable personal skills. The fixed source hashes for this adaptation are in `companion-skills-PROVENANCE.json`.

Service startup wires the native snapshot factory and uses the host's already-connected SDK when available. After a mutation releases the store lock, the service attempts an idle native refresh. The response preserves the durable historical receipt and reports the current attempt separately in `application`; refresh errors or busy sessions cannot turn a completed source save into a failed save. The existing native turn-ended hook retries pending application. Mount integration is under verification; real HTTP adapter tests use a controlled native-session fixture and do not establish installed Cindy behavior.

The original modern Capabilities layout is adapted separately with complete revision-bound personal pagination. Personal switches retain their original disabled behavior; no legacy remote editor is presented as the modern UI. The host candidate passed actual isolated Codex 0.160.1 catalog, independent-process, disabled-skill and body-only marker checks, including a changed body after resuming the same thread. This tests the host provider adapter, not the installed Cindy plugin or Claude execution. Production installation and visual acceptance remain separate gates.
