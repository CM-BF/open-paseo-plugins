# Original Cindy teammate packages

Source: <https://github.com/makecindy/cindy/tree/118767c987f518286ae10a506a54287c3dc2a560/apps/desktop/resources/bot-packages>

Pinned revision: `118767c987f518286ae10a506a54287c3dc2a560`.

`packages/` preserves all 100 published files, byte for byte, from the original ten `0.5.1` bundled teammate packages. The files contain 30 complete skills (including 10 getting-started skills), 10 evidence scripts, their templates, 10 method references, 10 WebP avatars and 18 disabled routine definitions. The original manifest preserves its identity, presentation, provenance and integrity metadata. This is the original bundled catalog, not a recreated cloud catalog.

`upstream-files.json` records every copied source file and original SHA-256. `packages.generated.ts` is generated by `scripts/generate-preset-assets.mjs`; its base64 payloads decode to the same source bytes. Only the server imports that payload map. The UI receives the original catalog projection, not the private import snapshot.

`catalog.ts` reuses the upstream `apps/desktop/src/main/bot-import/nativePackage.ts` parser and localized projection. The adaptation replaces the Electron resource-directory walk with a fixed, compiled byte map; package ID allowlisting, canonical manifest hashing, per-file integrity, file-size budgets, WebP signature, complete skill subtree, authored presentation references, localized copy and disabled-routine validation remain. Scheduler validation comes from the existing copied original scheduler. `types.ts` relocates type imports. `skill-validation.ts` extracts the original `botSkillStore.ts:577` import preflight; native packages never accept interpreter links. No package script is executed by catalog parsing.

## Rights evidence and public distribution boundary

The source-code license is the original Apache-2.0 license in `../../web/LICENSE-CINDY`, with `../../web/NOTICE-CINDY`. The upstream README's License section explicitly excludes an automatic blanket grant for prompts and separately identified materials. This record does not assert Apache-2.0 covers the package prompts, knowledge, or artwork.

Every avatar manifest records `rights.kind = "original"`, describes fictional animal artwork provided to the upstream author, and records `rights.review = "PENDING"`. Its `permissionEvidence` references `presentation/avatar-final-record.json`, which is **not among the published package files**. No separate artwork license or that evidence file was found in the pinned public package. These original declarations are retained without being converted into a new permission assertion. Public redistribution must disclose or resolve this evidence gap; local implementation does not establish those rights.

The manifests also retain the upstream original-source reference URLs and original-adaptation descriptions. They are provenance only, not network catalog endpoints, license grants, automatic connections, or claims that the referenced service works in Paseo.

## Original UI and behavior

The original `BotCreateMenu` opens `BotMarketDialog`. The catalog has no search/category filter: it is a two-column list, followed by a detail page with skills, knowledge/memory, tools and routines. Five authored content languages are retained; the current embedded Paseo shell exposes English and Simplified Chinese. Invitations use a package identity and a persisted import result; partial item failures remain visible and retry the original package. The host owns persistence, actual installed state, opening messages and activation.
